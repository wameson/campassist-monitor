# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- **Spec:** the authoritative design (schema, API contract, anti-blocking + write-budget rules, per-phase checklists) is `PLAN.md` in `~/workspace/firstmate/projects/camp-assist/` — read-only, lives outside this repo. The README summarizes the operator-facing parts.
- **Test:** `pytest` (config in `pytest.ini`; it puts `scripts/` and `tests/` on `sys.path` — modules import as `monitor`, `apns`, `db`, `common`, `providers.*`, fakes from `tests/helpers.py`). Python 3.12; install with `pip install -r requirements-dev.txt`. The suite must stay fully offline: no network, no real secrets.
- **Sharp edges:** runtime deps are deliberately capped at `httpx[http2]`, `PyJWT`, `cryptography`. A no-change monitor cycle must stay ≤5 Supabase writes (`test_write_budget` enforces it) — don't add per-watch writes. `scripts/*` take injectable HTTP clients/clocks; keep new code testable the same way. Never poll recreation.gov in tests; use `tests/fixtures/`.
- **Provider seam:** `monitor.run` is provider-neutral. Everything site-specific — request host, parsing, normalization to the shared `{site_id: {"campsite_id","site","dates"}}` availability shape, booking URL — lives behind the `Provider` protocol (`scripts/providers/base.py`), one conformer per `watches.provider` value, registered in `scripts/providers/__init__.py` (README "Providers"). Watches route by their `provider` column; a provider this build does not register is skipped untouched, never errored. Keep new cycle code provider-agnostic, and keep `PollKey[0]` the watch's own `campground_id` — the 404-strike lifecycle and `campgrounds_polled` are campground-scoped. Poll dispatch is anchored to the provider, never to the client-writable `campground_id`: the cycle plans `monitor.PollUnit` pairs (provider name, `PollKey`) via `poll_dispatch`, and the 404-strike inputs (`not_found`, `polled_ok`) plus the `extract_relevant` slice each conformer sees are per-provider, so a `campground_id` two providers share can never cross between them. Primitives both layers need (`as_date`, `capped_line`, `MAX_ERROR_MESSAGE_CHARS`) live in `scripts/common.py` so a provider never imports `monitor` (which imports it). Two invariants any new conformer must respect: `watches.campground_id` must match `monitor.CAMPGROUND_ID_RE` (`[A-Za-z0-9_-]+`) whatever the site's own id scheme looks like — anything else is errored before it is ever polled, so a namespaced id needs `gtc_…`, not `gtc:…`; and `poll_plan` runs **outside** the cycle's per-watch containment (`poll_dispatch`), so it must never raise — a watch it cannot plan for (e.g. an unusable `provider_ref`) plans nothing, and `extract_relevant`, which does run inside containment, is where that failure is raised.
- **Cycle resilience — containment & exit status:** per-watch work in `monitor.run` is contained — one watch's failure must never abort the cycle, and end-of-cycle bookkeeping (`run_summaries`, pruning) must always run. New watch writes go through `patch_watches` (batched, per-id fallback) and new failure paths through `record_failures`, so they count toward the systemic threshold that decides the run's exit status. A watch moves to `status='error'` **only** for a failure a write pinned to its own row (`PatchOutcome.isolated` / `isolated_failure`); table-scoped `sent_alerts`/APNs failures use `unattributed_failure` and must not error the watch. Keep loud failures loud: systemic breakage must still exit non-zero (README "Errors and run status").
- **APNs rating:** pass `rated=False` only for a per-device rejection (a dead device token / unbuildable push URL — `apns` `PERMANENT_FAILURE`): reported to both audiences but kept out of the exit-status rate. A pool-wide provider/config fault (`CONFIG_FAILURE` — expired/invalid/missing provider token, bad/disallowed topic) and every `RETRYABLE_FAILURE` (429/5xx/transport) stay rated, so a signing-key or bundle-id outage exits non-zero. A distinct backstop (`APNS_WIPEOUT_RATE`/`_FLOOR`) additionally turns the run systemic when outright rejections wipe out nearly every served push, catching reason codes `send_alert` does not enumerate.
- **Two rendering channels:** `run_summaries.errors` is **world-readable**, so it gets the `safe=True` rendering of `summarize_exception` (no watch UUIDs → per-run ordinals, no PostgREST `details`/`hint`, and for an exception with no response only its type name); the operator-only Action annotation gets the full rendering via `errors_detail`. Rules that keep this true as code is added: a failure reaches the row only through a rendering path (`watch_failures` per-watch, `record_cycle_failure` for the rest) — never by appending a pre-formatted message to the shared `errors` list, which is copied into the row verbatim, so anything that knows a watch id (e.g. `apns.send_alert`) hands back the *exception* and lets `run` attribute and render it; a user-supplied value (a rejected `campground_id`) reaches `errors` only as an aggregate count, with the value going to `detail_only`; everything on the shared channel goes through `capped_line` (which bounds the whole composed line, prefix included); and each cycle failure travels one channel per audience (`public_cycle_failures` → the row, `cycle_failures` → `cycle_errors`), because `failure_annotation` joins `errors_detail` and `cycle_errors` and a copy in both prints twice.
- **Schema changes:** editing `supabase/schema.sql` only affects fresh installs. Existing live DBs drift unless you also add an idempotent `supabase/migrations/NNNN_<desc>.sql` (see README "Database migrations"). Migrations are applied **manually** in the Supabase SQL editor by design — CI does not run them. `watches.provider_ref` is client-writable and carries identifiers only (`resource_location_id`, `map_id`); a provider's request host/URL is hardcoded/allowlisted in code and must **never** be derived from `provider_ref` (SSRF).
